# Contributing

Corrections should identify the exact v1 section, one-based PDF page, and the affected guide passage or metadata field. Explain whether the change concerns a transcription, a source discrepancy, an interpretation, or new external evidence.

Retain the source's reported precision and hypothesis verdicts. Record conflicts rather than choosing a convenient number. Identify a configuration, version and interval before proposing a taxonomy change. A source-code mechanism alone does not establish deployment authority semantics.

Run `python scripts/validate_repository.py`. Changes to citation metadata should also pass official CFF 1.2.0 schema validation. Keep author credit, source links, provenance and limitations current together. Do not upload the source PDF, original figures, complete extracted text, private transfer details, or unlicensed third-party implementation.

To add reproduction evidence later, document actual artifact acquisition, version/commit, environment, commands, deviations, and output comparisons. Receiving code is not the same as reproducing results. New versions of the paper require an explicit scope update.
